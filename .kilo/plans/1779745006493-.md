# Videco → Fully Functional Application Migration & Enhancement Plan

**Goal**: Transform the existing Videco Next.js codebase into a production-ready, fully functional AI Personalized Video Generation Platform for Cold Outreach, rebuilt on the mandated tech stack:

- **Supabase** (Edge Functions, Storage, Authentication)
- **Muapi** (primary image/video generation, effects, lipsync, orchestration)
- **Netlify** (hosting + Functions)
- **OpenAI** (Responses API, Realtime API, LLM for personalization/scripting)

**Current State (Audit Summary)**:
- Next.js 13 (pages router) + Chakra UI + Zustand + next-i18next
- Supabase (auth, Postgres, realtime, RLS) – profiles, videos, leads, analytics, plan, jobs, ai_videos, feedback, sub_accounts
- Heavy Cloudinary usage (upload, storage, video transforms, serving)
- Inngest background jobs for AI video processing & lipsync
- Sync.so for lipsync / AI clone (video + audio → talking head)
- Speechify for AI voice cloning + TTS (hardcoded keys in code)
- Stripe (subscriptions, trials, webhooks, one-time)
- Vercel deployment (vercel.json with 60s function timeout)
- Complex Editor v2 (timeline, elements, interactive CTAs, forms, calendars)
- Interactive Player that captures leads/feedback
- Campaigns, AI Clones, Analytics, Leads, Brand Kit flows
- No OpenAI, no Muapi, no Netlify config today

**Target Architecture**:
- **Frontend**: Unchanged stack (Next.js on Netlify)
- **Auth**: Supabase (existing + Edge Function JWT validation where needed)
- **Storage**: Supabase Storage (user uploads) + Muapi CDN (AI-generated assets)
- **Video/Image AI**: Muapi (text-to-video, image-to-video, lipsync/omni-reference, effects, audio-video sync)
- **Personalization & Scripting**: OpenAI LLM + Responses API (structured outputs for personalized scripts, email copy, video narration per lead)
- **Voice**: OpenAI Realtime API / TTS (or Muapi audio models) – replace Speechify
- **Background / Long-running**: Supabase Edge Functions (orchestrate Muapi submit/poll, webhooks, Inngest replacement)
- **Serverless APIs**: Netlify Functions (migrate most `/pages/api/*` routes)
- **Webhooks**: Stripe, Muapi, Supabase → handled in Edge/Netlify Functions
- **Hosting**: Netlify (Next.js + Functions + Forms if useful)
- **Jobs/Orchestration**: Deprecate Inngest; use Supabase Edge Functions + Muapi webhooks + OpenAI tool calling

## Phase 1: Foundational Infrastructure Migration (3-5 days)

### 1.1 Netlify Hosting & Functions Setup
- Install Netlify CLI.
- Create `netlify.toml`:
  - `[build] command = "yarn build"`, publish = "out" or `.next`
  - Functions directory: `netlify/functions`
  - Edge Functions if beneficial
  - `[functions] node_bundler = "esbuild"`
- Migrate critical API routes from `pages/api` to Netlify Functions (or keep hybrid during transition):
  - Stripe webhook handler (critical – must move early)
  - Auth helpers / token verification
  - Video processing triggers
- Update `vercel.json` removal + GitHub Actions (or use Netlify Git integration).
- Update `next.config.js` if needed for Netlify image optimization / trailing slashes.
- Test `netlify dev` locally with Supabase local.

### 1.2 Supabase Edge Functions
- Initialize Supabase Edge Functions (`supabase functions new`).
- Port key background logic:
  - `ai/process` (voice + background + combine)
  - `ai/clone` (lipsync)
  - General Muapi orchestration + polling + status updates
- Use Deno + `@supabase/supabase-js` + fetch for Muapi/OpenAI calls.
- Secure with Supabase JWT verification (use existing `verifyToken` logic or service role keys carefully).
- Deploy: `supabase functions deploy`.
- Set secrets via `supabase secrets set MUAPI_API_KEY=...`.

### 1.3 Storage Migration Strategy
- Add Supabase Storage bucket(s): `user-uploads`, `ai-assets` (or rely on Muapi CDN for generated).
- Create upload flow using Supabase Storage (replace direct Cloudinary in `/api/upload`, recorder, editor upload).
- For existing Cloudinary assets: build one-time migration script (or leave as-is with dual CDN support during transition).
- Update all `<img>` / `<video>` / `ReactPlayer` sources to support both origins (feature flag or gradual cutover).

### 1.4 Authentication Hardening
- Ensure all new Edge/Netlify Functions validate Supabase JWTs.
- Update `middleware.ts` if present for protected routes.
- Test magic links, OAuth, session refresh on Netlify.

## Phase 2: Core AI Video Generation – Replace Sync + Speechify + Cloudinary with Muapi + OpenAI (5-8 days)

**Critical Path Feature**: Personalized AI video creation (AI Clone / Campaign video with custom voice + script).

### 2.1 Muapi Integration Layer
- Create `src/services/muapi.ts` (or `lib/muapi`):
  - Unified submit + poll helper (Muapi uses request_id + `/predictions/{id}/result`)
  - Webhook handler support
  - File upload helper (`/api/v1/upload_file`)
- Model selection matrix (document + code):
  - High-quality lipsync/talking head: `kling-master` + audio ref or dedicated lipsync/effects endpoint if available; or `sd-2-omni-reference` / ByteDance models for reference consistency
  - Fast social clips: `seedance-lite`, `hunyuan`, `pixverse`
  - Cinematic: `veo3`, `kling-pro`
  - Image-to-Video personalization: reference uploaded headshot + prompt
  - Audio/Video sync: Muapi "lipsync", "ai-video-face-swap", or omni-reference models
- Replace all Cloudinary video generation/transcode calls.

### 2.2 Voice & Lipsync Replacement
- Deprecate Speechify (`src/services/api/aiVoice.ts`).
- New flow:
  1. OpenAI Realtime API or TTS for high-quality voice synthesis (or Muapi audio/music-speech models).
  2. Voice cloning: evaluate Muapi face/voice models or OpenAI voice capabilities; fallback to user-provided audio sample + Muapi reference.
  3. Lipsync: send base video + generated audio to Muapi lipsync/omni model → poll → store result URL in Supabase `videos.ai_preview` or new `ai_outputs` table.
- Update `src/services/aiClone.ts` and Inngest functions → move logic to Supabase Edge Function.
- Update callers in:
  - `pages/api/v1/videos/clone.ts`
  - `pages/api/v1/videos/process.ts`
  - `src/components/features/editor-v2/...` (generate steps)
  - `pages/clones/create.tsx`
  - `pages/campaign/steps/start.tsx`

### 2.3 OpenAI LLM for Personalization (New Capability)
- Create `src/services/openai.ts`:
  - Responses API for structured JSON outputs (personalized script per lead: name, company, pain point → greeting + 30-60s narration).
  - Realtime API for live voice preview / script refinement (optional advanced feature).
- New endpoints / UI:
  - "Generate Personalized Script" button in campaign/lead flow.
  - Store generated script in `videos.elements` or new `personalization` JSONB column.
- Use LLM to vary intros/outros per recipient while keeping core message consistent.

### 2.4 Background Job Consolidation
- Remove or keep Inngest as optional (plan to deprecate).
- All long-running AI work → Supabase Edge Functions triggered by:
  - Direct API call from frontend (with job row in DB)
  - Muapi webhook callbacks (update status, store final URL)
- Add `jobs` / `ai_jobs` table enhancements if needed (already partially exists).
- Implement reliable polling + webhook fallback.

## Risks & Mitigations

- **Muapi lipsync quality** < Sync.so: Prototype 2-3 models early; have fallback to user-provided audio-only or keep Sync for premium tier.
- **Netlify function cold starts / duration**: Use Edge Functions for orchestration; keep heavy work async.
- **Cost explosion** (Muapi credits + OpenAI): Strict per-user quotas, pre-generation estimates, admin alerts.
- **Data migration pain**: Dual-CDN strategy + gradual cutover.
- **Voice cloning legal/consent**: Keep existing consent flow; document new provider terms.
- **Realtime API rate limits**: Graceful degradation to standard TTS.
